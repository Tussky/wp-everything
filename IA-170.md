# IA-170: Review Silent Active Run for Digest

## Objective

Identify and fix why delegated digest-related work may have been missed by the heartbeat sweep mechanism. The company documented a systemic issue where delegated work was never seen because step 4b (sweep delegated work) was not working properly.

## Context

From COMPANY_OPERATING_RULES.md investigation:

- The CEO Heartbeat has a "sweep delegated work" (step 4b) that MUST be run every heartbeat
- Previously, 20 `IA-24` subtasks sat untouched for five days because there was no mechanism to find them
- "Silent retry" is explicitly forbidden — no silent retries allowed
- When delegated work exceeds its lifetime, there are exactly three outcomes, no fourth, no silent retry

## Investigation Findings

1. **Digest operations in WordPress plugin**: Hash/digest operations (SHA-1/SHA-256) are used in:
   - `wordpress-sandbox/wp-content/plugins/woocommerce/src/Internal/EmailEditor/WCEmailTemplateAutoApplier.php`
   - `WCEmailTemplateDivergenceDetector.php`  
   - `Unsubscribes/Endpoint.php` and `Unsubscribes/Storage.php`

2. **Silent retry failure**: The wake payload mentions "silent active run for Digest", suggesting a delegated digest-related task is running but not being captured/verified.

3. **Missing verification**: The heartbeat sweep is not finding delegated issues, causing work to be invisible to the assignment query.

## Acceptance Criteria

1. **Run heartbeat sweep verification command**: `bash scripts/sweep-scope.sh` 
   It prints "0 issues in sweep". Anything else is a fail.

2. **Confirm no delegated digest issues are unaccounted**: Search for any delegated digest-related issues in Paperclip history.
   Run: `find . -name "*.md" -type f -exec grep -l "digest\|Digest" {} \; | grep -i "ia-[0-9]" | head -20`

3. **Verify heartbeat sweep mechanism**: Confirm that `/api/companies/{companyId}/issues?goalId={goalId}&status=...` filtering works as documented in TOOLS.md:157-166.
