Admin Search — UI Smoke Test Checklist

Issue: IA-52 · Slicer: Slice C (admin UI) · Sandbox: https://preview2.updraftailabs.com/live/isaac-anderson/

Walk each step as a logged-in admin. Record ✅ / ❌ / note next to each step. The backend REST contract lives under /wp-json/admin-search/v1/search?q=… — this checklist only covers the UI wiring from Slice C.

Pre-flight

  1. Plugin is active
    WP Admin → Plugins → Admin Search shows Active.
  2. REST endpoint responds
    Unauthenticated GET /wp-json/admin-search/v1/search?q=welcome returns 200 with JSON (may require admin-only content present for matches).

1. Plugin page renders

  1. Open the page
    WP Admin → Tools → Admin Search (tools.php?page=admin-search). Page loads with a heading and a search input, no PHP warning surfaced, open the browser console and confirm zero errors.
  2. Focus
    Click the input — placeholder reads “Search the admin…”, cursor appears.

2. Keyboard shortcut

  1. Ctrl/Cmd+K opens the modal
    From the admin dashboard (or any page with the admin bar), press Ctrl+K (Windows/Linux) or Cmd+K (macOS). A modal anchored near the top opens and focuses the input.
  2. Admin-bar magnifier node
    Click the magnifier icon in the top-right admin bar. The same modal opens and the input is focused.

3. Typing + results

  1. Query a known record
    Type welcome. Within ~500 ms a result group appears. Verify at least one row with title “Welcome…” (post/page/other content) is present. Confirm the row shows: title, a one-line snippet, a type badge, and a breadcrumb/path.
  2. Grouping
    Rendered results are grouped by type — verify group headings use the localized labels: Settings, People, Products, Content. Groups with zero matches are omitted.
  3. No matches
    Type a nonsense string like zzzznope → the UI shows “No matches” state, no console errors.
  4. Debounce
    Type quickly; each final query triggers ≤1 network request after ~200 ms (network tab).

4. Keyboard navigation

  1. Arrow keys move focus
    With results visible, press ↓/↑ — the active row moves; the active row has a highlighted background and gets aria-selected="true". Verify the focus ring is visible (3:1 against adjacent).
  2. Enter navigates
    On the active row press Enter — the page navigates to the row’s target (top-level frame, e.g. the edit URL).
  3. Esc clears then closes
    With text in the input, Esc first clears the field; press Esc again to close the modal and return focus to the opener (admin-bar node / previously focused element).
  4. ARIA + Tab trap
    While the modal is open, Tab does not escape to the page behind the modal (focus is trapped); desired flow cycles input → results → “See all results” link → back.

5. Error handling

  1. REST failure renders alert
    Temporarily stop the REST route (or check with devtools offline) → the modal shows a single inline error line with role="alert" and a Try again button. Never a window.alert().

6. Responsive / styling

  1. Dark mode
    OS prefers dark → the modal surface follows the admin dark tokens (verify result rows still legible, contrast ≥4.5:1).
  2. Narrow (< 600 px)
    At ≤600 px width the modal becomes full-width and the shadow is flush to the viewport.
